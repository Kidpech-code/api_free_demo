📖 API Reference — v1.0
Product Sandbox API
REST API สำหรับทดสอบและเรียนรู้การออกแบบ Backend ด้วย Clean Architecture + Redis DocStore Pattern ทุก request ถูก shard ด้วย user_id — ข้อมูลมีอายุ 72 ชั่วโมงแล้ว expire อัตโนมัติ
🌐

Base URL: http://localhost:8080  ·  Authenticated endpoints: /api/v1/* ต้องใส่ Authorization: Bearer <token> header ทุก request

🔐 Authentication

ระบบใช้ JWT (HS256) — token สร้างได้ผ่าน GET /auth/token?user_id=xxx

💡

ทุก request ที่ส่งไป /api/v1/* ต้องมี header: Authorization: Bearer <YOUR_TOKEN>
Token ผูกกับ user_id ของคุณ — ข้อมูลทุกอย่างถูก namespace โดยอัตโนมัติ ทำให้ User A ไม่มีทางเข้าถึงข้อมูล User B ได้ (Strict Isolation)

# ขั้นตอน 1: ขอ Token curl "http://localhost:8080/auth/token?user_id=alice" # ขั้นตอน 2: ใช้ Token ใน Request ทุกตัว curl -H "Authorization: Bearer eyJhbGci..." \ "http://localhost:8080/api/v1/products"

🚦 Rate Limiting

Fixed Window Counter ด้วย Lua Script (Atomic) — 100 requests/minute ต่อ user_id

⚠️

เมื่อเกิน limit จะได้รับ HTTP 429 พร้อม header Retry-After บอกเวลาที่ต้องรอ

X-RateLimit-Limitจำนวน request สูงสุดต่อ window (default: 100)
X-RateLimit-Remainingrequest ที่เหลือใน window ปัจจุบัน
X-RateLimit-ResetUnix timestamp ที่ window จะ reset
Retry-Afterจำนวนวินาทีที่ต้องรอก่อน retry (ส่งเมื่อ 429 เท่านั้น)

⚠️ Error Format

Error ทุกตัวส่งกลับในรูปแบบ JSON envelope เดียวกัน

{ "success": false, "error": "คำอธิบาย error" }

📦 Product Endpoints

ทุก endpoint ต้องการ Authentication · ข้อมูลถูก shard ด้วย user_id · TTL 72 ชั่วโมง

GET /api/v1/products List products (Cursor Pagination) 🔐 Auth ›
🗺️

ใช้ ZREVRANGEBYSCORE บน Redis ZSET index — ผลลัพธ์เรียงตาม creation time (descending) รายการใหม่สุดอยู่บน cursor คือ score ของรายการสุดท้ายในหน้าปัจจุบัน

Query Parameters
ParamTypeDefaultDescription
cursorstring—Score จากหน้าก่อนหน้า (ค่า next_cursor ใน response)
limitint20จำนวนรายการ (1–100)
Response 200
{ "success": true, "data": [ /* Product[] */ ], "meta": { "count": 20, "has_more": true, "next_cursor": "1771389457123456789" } }
ตัวอย่าง cURL
# หน้าแรก curl -H "Authorization: Bearer $TOKEN" \ "http://localhost:8080/api/v1/products?limit=10" # หน้าถัดไป (ใช้ next_cursor) curl -H "Authorization: Bearer $TOKEN" \ "http://localhost:8080/api/v1/products?cursor=17713&limit=10"
Product Schema

GET /api/v1/products/:id ดึง product ตาม ID (Integrated Cache) 🔐 Auth ›
⚡

ใช้ Integrated Cache Pattern: อ่านจาก _cache key ก่อน → cache hit ส่งกลับทันที → miss → อ่านจาก data key → backfill cache อัตโนมัติ

Path Parameters
ParamTypeDescription
idstring (UUID)requiredProduct UUID
404 Not Found
{ "success":false, "error":"resource not found: product xxx" }
ตัวอย่าง
curl -H "Authorization: Bearer $TOKEN" \ "http://localhost:8080/api/v1/products/88955c72-058a"
PUT /api/v1/products/:id อัปเดต product (Write-Invalidate) 🔐 Auth ›

FieldTypeDescription

💡 Write-Invalidate: Cache key ถูก DEL ทันที — อ่านครั้งถัดไปจะ backfill จาก storage key ใหม่
DELETE /api/v1/products/:id Soft delete + ลบออกจาก ZSET index 🔐 Auth ›
🗑️

Soft Delete: SET deleted: true บน data key + DEL cache key + ZREM จาก index — record ยังอยู่ใน Redis แต่ไม่ปรากฏใน List อีกต่อไป จะหายไปเองเมื่อ TTL หมด

200 OK
{ "success": true, "data": { "deleted": true } }
ตัวอย่าง
curl -X DELETE \ -H "Authorization: Bearer $TOKEN" \ "http://localhost:8080/api/v1/products/<id>"
POST /api/v1/products/bulk Bulk create ด้วย Redis Pipeline 🔐 Auth ›
📦

Uber-Style Batch Optimization: คำสั่ง SET + ZADD + EXPIRE ทุกรายการถูกส่งใน pipeline เดียว — ลด network round-trips จาก N×3 ลงเหลือ 1 batch การส่ง score offset ทำให้ ordering ภายใน batch ถูกต้อง

Request Body
{ "items": [ { "name": "Item A", "price": 9.99, "sku": "A-01" }, { "name": "Item B", "price": 14.99, "sku": "B-01" } ] }
Limits
• สูงสุด 100 items ต่อ request
• ทุก item ต้องมี name และ price > 0
ตัวอย่าง
curl -X POST \ -H "Authorization: Bearer $TOKEN" \ -H "Content-Type: application/json" \ -d '{"items":[{"name":"A","price":9.99},{"name":"B","price":14.99}]}' \ "http://localhost:8080/api/v1/products/bulk"
201 Created
{ "success": true, "data": { "created": 2 } }
